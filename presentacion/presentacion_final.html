Introducción

Hay más pedidos de los que
se pueden controlar a mano

Cada repartidor informa a su manera

Logística no sabe qué rutas terminaron.

Entregas fallidas sin motivo

Lo que no se registra no se puede corregir.

Avisos al cliente hechos a mano

Llegan tarde y con errores.

Nuestra solución: cada ruta del día se guarda en un solo documento, con su repartidor, sus comunas y sus paradas.

Tecnologías: MongoDB Atlas y VS Code

La ruta de Pedro

codigo: "R1", estado: "en_ruta", km: 42, activo: true, fecha: new Date(),
repartidor: { nombre: "Pedro Muñoz", telefono: "987654321" },
comunas: ["Puerto Montt", "Alerce"],
paradas: [ { cliente: "Ana Paz", monto: 30000, estado: "entregada" }, { cliente: "Luis Rojas", monto: 25000, estado: "fallida", motivo: "cliente ausente" } ]
Campos simplesTexto, número, booleano y fecha.
Subdocumento { }Cada ruta tiene un repartidor: se leen juntos.
Arreglo [ ]Una ruta pasa por varias comunas.
Arreglo de subdocumentosMuchas paradas, cada una con sus datos.

Operaciones CRUD · ahora, en vivo en VS Code

Un día de reparto en cuatro pasos

C
CrearSe agrega una ruta
db.rutas.insertOne({ codigo: "R10", estado: "en_ruta" })insertOne agrega un documento
R
LeerEntregas que fallaron
db.rutas.find({ "paradas.estado": "fallida" })find busca · el punto entra en cada parada
U
ActualizarPedro avanzó 5 km
db.rutas.updateOne({ codigo: "R1" }, { $inc: { km: 5 } })updateOne cambia un documento · $inc suma al valor actual
D
EliminarRutas de prueba
db.rutas.deleteMany({ estado: "prueba" })deleteMany borra todos los que cumplen la condición
